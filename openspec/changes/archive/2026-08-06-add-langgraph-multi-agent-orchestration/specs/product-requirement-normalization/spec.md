## ADDED Requirements

### Requirement: 标准 PRD 结构化输出
需求解析智能体 SHALL 把非空产品需求转换为符合版本化 `StandardizedPRD` Schema 的对象，至少包含产品目标、目标用户、问题、范围、页面、用户流程、内容需求、组件需求、交互与状态、响应式要求、可访问性要求、业务约束、假设和未决问题。

#### Scenario: 解析完整产品需求
- **WHEN** 输入描述了产品目标、用户、页面和主要流程
- **THEN** 输出将信息归入对应结构化字段，并通过 StandardizedPRD Schema 校验

#### Scenario: 拒绝空需求
- **WHEN** 输入为空、仅包含空白或超过配置的最大字节数
- **THEN** 智能体在调用模型前返回稳定输入错误

### Requirement: 缺失信息显式表达
需求解析智能体 MUST 将无法从输入确定但会影响 UI 设计的信息记录为 `openQuestions` 或带来源的 `assumptions`，不得把推测伪装为用户已确认事实。缺失信息不阻断安全默认设计时 SHALL 产生标准 PRD；关键冲突无法消解时 SHALL 返回失败。

#### Scenario: 使用安全假设
- **WHEN** 需求未指定目标设备但明确描述普通后台管理页面
- **THEN** 输出可记录桌面优先且需要窄屏适配的假设，并保留设备策略未确认的信息

#### Scenario: 关键需求冲突
- **WHEN** 输入同时要求公开匿名访问和所有访问必须企业登录，且没有优先级信息
- **THEN** 智能体把冲突列为阻断问题，不向 UI 设计阶段输出伪确定需求

### Requirement: 需求可追溯与语义保真
标准 PRD SHALL 为页面、流程和关键约束保留稳定标识，并区分明确需求、推导假设和未决问题。解析过程 MUST NOT 删除用户明确声明的合规、可访问性、平台、品牌或业务限制。

#### Scenario: 保留明确约束
- **WHEN** 输入明确要求 WCAG AA、移动端优先和禁止使用模态框
- **THEN** 输出在可访问性、响应式和交互约束中分别保留这些要求

### Requirement: 标准 PRD 输出确定性门禁
模型返回结果后，系统 MUST 执行 JSON Schema 校验、稳定 ID 唯一性检查和跨引用检查。校验失败时只允许一次带结构化错误反馈的修复重试，重试后仍无效则失败关闭。

#### Scenario: 页面流程引用不存在页面
- **WHEN** 模型输出的用户流程引用 StandardizedPRD 中不存在的页面 ID
- **THEN** 输出门禁拒绝结果并返回可定位的引用错误
