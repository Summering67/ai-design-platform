## Context

`packages/ui` 当前没有通用 Tree 控件，编辑器或业务调用方若展示层级数据，需要自行实现节点索引、展开扁平化、选择、勾选传播、搜索、异步加载与拖拽状态。Semi Design 的 Tree 将递归节点数据、组件 Props、内部派生状态和拖拽事件分开，这一分层适合参考；但其宽泛字段、`any` 类型和大量平铺 Props 不符合本仓库明确类型与小型公共接口的要求。

本变更只建设 React 运行时控件。`TreeNodeData` 是调用方传入的规范运行时数据，任意领域模型均由调用方先行适配。

## Goals / Non-Goals

**Goals:**

- 提供泛型、递归、稳定 key 的运行时 Tree 数据接口。
- 在同一控件中提供展开、选择、勾选、搜索、异步加载、拖拽和虚拟化能力。
- 每个状态轴同时支持受控与非受控模式，并保持事件载荷稳定。
- 隐藏节点索引、扁平列表、半选传播和搜索路径计算等复杂实现。
- 提供语义化 Tree、键盘导航、清晰焦点和可组合渲染能力。
- 复用 `packages/ui` 的现有依赖和子路径导出规则。

**Non-Goals:**

- 不在 Tree 内部请求业务接口、持久化业务数据或修改调用方传入的 `treeData`。
- 不提供跨树拖拽、服务端搜索协议、权限模型或业务菜单语义。
- 不复制 Semi Design 的源码、样式或完整 Props 命名。

## Decisions

### 运行时节点使用固定最小字段与泛型业务载荷

公开节点以 `key`、`label`、`children`、`icon`、`disabled`、`disableCheckbox`、`isLeaf` 和可选泛型 `data` 组成。`key` 必须为非空字符串并在整棵树内唯一；不提供 `keyMaps`，调用方必须先把任意领域模型转换为规范运行时节点。

固定小接口让索引、无障碍属性和事件始终围绕同一稳定 key 工作，也避免控件内部了解业务字段。曾考虑像 Semi 一样支持任意字段映射，但这会扩大类型和运行时分支，并把数据适配复杂度放进公共模块，因此不采用。

### 能力通过分组配置表达，状态轴保持受控与非受控对称

`TreeProps<T>` 保留 `treeData`、`disabled`、`className` 等顶层基础字段，把选择、勾选、搜索、加载、拖拽和虚拟化分别放入明确配置对象。展开作为所有 Tree 都具备的基础状态，提供 `expandedKeys`、`defaultExpandedKeys` 和 `onExpandedChange`；其他状态轴也采用 `value/defaultValue/onChange` 的对称模型。

同一状态轴不得同时由内部状态和受控值驱动。受控值存在时，用户操作只发出事件；调用方未回传新值前，显示状态保持不变。这样比大量相互影响的布尔 Props 更容易测试，也让模块接口保持集中。

### 内部从递归数据派生索引和可见扁平列表

实现每次在 `treeData` 结构变化时构建私有 key 索引，记录父级、深度、同级位置和节点引用；再根据展开、搜索和加载状态派生可见扁平列表。索引与扁平节点不导出、不持久化，虚拟化和普通渲染共享同一份派生结果。

这让勾选传播、祖先展开、键盘移动和 `scrollToKey` 集中在 Tree 模块内部。直接递归渲染虽简单，但会让搜索、键盘与虚拟化分别重复遍历，因此不采用。

### 勾选与选择是独立状态

选择用于焦点对象或业务选中项，支持 `none`、`single` 和 `multiple`；勾选由 `checkable` 配置开启，支持 `related` 和 `independent` 两种关系。`related` 模式向可勾选后代传播，并由后代计算祖先半选；禁用或 `disableCheckbox` 节点不被传播修改。`leafOnly` 只把叶节点返回为业务 checked keys，但仍计算祖先视觉状态。

选择与勾选不共用一个 `value`，避免调用方必须理解模式相关的联合类型。

### 搜索是运行时派生视图

搜索配置支持受控与非受控文本、自定义 `filterNode`、自动展开匹配节点祖先以及 `showMatchedOnly`。搜索不得修改调用方的 `expandedKeys`；控件单独派生搜索展开集合，清空搜索后恢复搜索前的展开视图。标签高亮由默认渲染器或渲染上下文的 `matched`、`searchValue` 信息完成。

曾考虑过滤后重写 `treeData`，但会破坏 key 索引、加载状态和受控展开语义，因此不采用。

### 异步加载只协调状态，不拥有业务子节点

当非叶节点没有 children 且提供 `loadChildren` 时，首次展开调用该函数。控件维护或接收 `loadedKeys`，在 Promise 期间标记 loading；成功后发出 loaded 变化，调用方负责把新 children 写回 `treeData`；失败后清除 loading 且不标记 loaded，允许再次展开重试。同一 key 的并发请求只执行一次。

该设计与受控数据流一致，也避免 Tree 内部持有一份与调用方不同步的节点副本。

### 拖拽只发出结构化落点意图

拖拽配置启用后，控件计算 `before`、`inside`、`after` 三种落点，并向 `canDrop` 与 `onDrop` 提供 `{ dragKey, targetKey, position }`。Tree 不直接重排 `treeData`；调用方收到意图后更新数据。控件必须拒绝拖入自身或后代，并允许调用方基于业务规则拒绝落点。

Semi 的 DOM 事件、相对数字位置和内部节点实例不进入公共载荷，避免接口暴露实现细节。

### 渲染扩展围绕节点上下文而非内部 DOM

默认渲染器负责缩进、展开按钮、图标、勾选框、标签和状态样式。调用方可配置 `renderLabel`、`renderIcon`、`renderNode` 和 `emptyContent`；渲染上下文只暴露节点、深度、展开、选择、勾选、半选、禁用、加载、匹配等稳定状态与必要动作，不暴露私有索引或虚拟列表对象。

### 普通列表与虚拟列表共享行为模型

未提供虚拟化配置时渲染完整可见列表；启用后使用现有 `react-virtuoso` 渲染同一扁平列表，并支持高度、overscan 和 `scrollToKey`。虚拟化不得改变选择、键盘、搜索、拖拽和无障碍事件语义。

### 遵循 WAI-ARIA Tree 交互

根元素使用 `role="tree"`，节点使用 `role="treeitem"` 与 `aria-level`、`aria-expanded`、`aria-selected`、`aria-checked`。控件使用 roving tabindex 管理单一焦点节点，支持方向键、Home、End、Enter 和 Space；隐藏或被过滤节点不得保留可聚焦状态。

## Risks / Trade-offs

- [单个控件承载能力较多，公共类型可能膨胀] → 使用分组配置和稳定节点上下文，避免为每个细节增加顶层 Props。
- [递归数据在调用方每次渲染时重建会导致索引和扁平列表重复计算] → 按 `treeData` 引用与状态轴 memoize 派生结果，并在文档中要求调用方稳定数据引用。
- [虚拟列表中的 WAI-ARIA 集合信息可能与未挂载节点不一致] → 显式提供 `aria-posinset` 与 `aria-setsize`，并通过组件集成测试覆盖虚拟化键盘导航。
- [原生拖拽对触摸与键盘支持有限] → 本期将拖拽定义为指针能力，键盘仍完整支持浏览、展开、选择和勾选；键盘重排作为后续能力。
- [异步加载成功但调用方未及时回传 children 会显示空节点] → loading/loaded 与数据内容分开，保留空状态并允许调用方通过受控 loaded keys 修正状态。
- [仓库当前缺少 `packages/ui` 组件测试入口] → 实施前确认可复用的单元/组件测试工具；若必须新增测试依赖，只加入实现本需求所需的最小开发依赖，不新增运行时依赖。

## Migration Plan

1. 定义运行时节点、配置、事件和句柄类型，再实现不含 React DOM 的索引、扁平化、搜索与勾选纯函数。
2. 实现基础 Tree 语义、受控状态和默认节点渲染。
3. 接入异步加载、拖拽、搜索和渲染扩展。
4. 接入 `react-virtuoso` 与 `scrollToKey`，统一普通和虚拟模式行为。
5. 增加单元测试与组件集成测试，完成 `packages/ui` 的 lint 和类型检查。

该能力为新增公开模块，没有存量调用方迁移。回滚时删除 Tree 模块及新增的测试开发依赖即可，不涉及数据迁移。

## Open Questions

无。首期使用字符串 key、单树拖拽、指针重排，并由调用方拥有异步 children。
