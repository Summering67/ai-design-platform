# @repo/ui 共享组件规范

## 定位

`packages/ui` 是供 `apps/*` 使用的共享 React UI 包，包含 shadcn/ui 基础组件、全局主题样式和不依赖应用环境的界面组件。

修改本目录时，同时遵守仓库根目录的 `AGENTS.md`。

## 收录范围

适合放入本包：

- 被多个应用实际使用的基础 UI 组件。
- API 稳定且不包含具体业务语义的通用组件。
- 与具体路由、权限、接口和应用状态无关的展示或交互能力。
- 通过 Props 和回调接入应用能力、不直接依赖框架路由的界面组件。

不适合放入本包：

- 页面、路由和应用布局。
- 只服务于单个应用的业务组件。
- 接口请求、业务状态和领域逻辑。
- 依赖具体应用文案、环境变量或数据结构的实现。

## 依赖边界

- 禁止引用 `apps/*` 中的代码。
- 禁止依赖 Next.js 路由、服务端能力或应用级配置。
- 不读取具体应用的环境变量。
- 不在组件内部执行接口请求或持久化业务状态。
- 组件通过 Props、回调和组合能力与应用交互。
- 新增依赖前确认其属于共享组件层，并避免引入功能重复的库。

## 组件实现

- 使用函数式组件和明确的 Props 类型。
- 不使用 `any`、非必要类型断言或冗余包装组件。
- 公共 API 保持简洁，不暴露内部实现细节。
- 优先使用组合扩展能力，不为单个业务场景增加专用 Props。
- 新增或修改共享组件时，不引入 `alert`、日志、导航或其他应用级副作用。
- 参数无效或内容为空时提前返回。
- 原生元素 Props 应尽量透传，避免无理由限制标准能力。
- 交互组件必须支持语义化标签、键盘操作和清晰的焦点状态。

## 文件与导出

- shadcn/ui 基础组件放在 `src/components/<name>.tsx`。
- 组合界面放在 `src/blocks/<name>/index.tsx`，其 CSS Module 放在同一目录。
- 工具函数放在 `src/lib`，类型声明放在 `src/types`。
- 全局主题样式统一由 `src/styles/globals.css` 提供。
- 组件及其公共 Props 类型使用命名导出。
- 包内组件相互引用时使用相对路径。
- 应用必须通过 `@repo/ui/components/<name>` 导入基础组件。
- 组合界面通过 `@repo/ui/blocks/<name>` 导入，工具函数通过 `@repo/ui/lib/<name>` 导入。
- 禁止跨包引用 `packages/ui/src` 内部路径。
- 新增组件必须符合 `package.json` 中现有的子路径导出规则。
- 不导出只服务于内部实现的函数、常量或类型。

## 修改原则

- 修改公共组件时检查所有应用调用方，避免无提示的破坏性变更。
- 优先保持现有 API 兼容；确需调整时同步修改受影响的调用方。
- 不为临时业务需求扩展公共组件。
- 不顺带重构未涉及的组件。
- 修改后使用本包已有的 lint 和类型检查入口进行验证。
